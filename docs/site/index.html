What developers told Stack Overflow in 2023 and 2024

Every year Stack Overflow asks developers around the world about their work and tools. This page tells the story of two of those surveys. A data pipeline cleaned the raw answers and checked them before anything was shown here.

89,184people in the 2023 survey
65,437people in the 2024 survey

Keep this in mind: fewer people answered in 2024, so many counts below are smaller. That is not a sign that developers left. Compare the order of the lists and the gaps between rows, not the raw size across years.

Chapter 6

How the numbers got here

A pipeline built with Apache Airflow, dbt and PostgreSQL turns the raw survey files into these results. It has 10 steps:

  1. open_release Creates a new, empty release for this run.
  2. ingest_raw_survey Loads the survey file into the database.
  3. record_source_checksum Saves a fingerprint of the file, so we know exactly what was loaded.
  4. run_dq_checks Runs seven data quality checks. A blocking check stops everything.
  5. dbt_seed Loads small lookup tables, such as currency rates.
  6. dbt_run_models Builds the cleaned tables and the three result tables.
  7. dbt_test_models Tests the result tables. A failure stops the run here.
  8. mark_candidate Marks the release as ready, but not live.
  9. publish_release Moves the live pointer to this release. Only this step changes what readers see.
  10. render_dashboard Builds the results page from the live release.

Seven checks guard the raw file:

  • null_response_id catches a row without an ID.
  • duplicate_response_id catches the same ID twice.
  • null_country catches a missing country.
  • null_comp_total catches missing pay.
  • invalid_years_code_pro catches impossible years of coding.
  • total_rows_loaded catches an empty load.
  • row_count_drop catches a file with less than half the rows of the last published release.

The key idea: results are built as a candidate and only become live at publish_release. If a test fails before that, the last good release stays live.

The honest part: the pipeline was tested with six deliberate failures. One of them, a truncated file, was published as the live release. That is why the seventh check, row_count_drop, was added. One weakness is still open: Airflow's own database shares the same Postgres instance as the warehouse, so killing Postgres also stops the scheduler. The notes are in the repository.

Glossary

Words used on this page

Median
The middle value: half of the group earns more, half earns less. It is less thrown off by a few very high salaries than an average.
Average
All values added up and divided by the number of people.
Release
One complete, tested copy of the results from one pipeline run. Only one release per year is live.
Candidate
A release that is built and tested but not live yet.
Publish
Make a candidate the live release.
Group (cell)
One slice of people who share the same country, experience, role, remote-work and company-size answers. A group only appears if enough people are in it.
Pipeline
The chain of steps that takes the raw survey file and produces these results.
Data quality check
An automatic test on the raw file, such as 'no missing IDs'.
